# CurePaw — Информационная система для ветеринарной клиники

Десктопное приложение для автоматизации процессов ветеринарной клиники: ведение учета клиентов и пациентов, запись на прием, управление расписанием сотрудников, администрирование каталога услуг и автоматический расчет стоимости визитов.

Проект разработан в рамках курсового проектирования по специальности 09.02.07 «Информационные системы и программирование».


## Стек технологий

* **Язык разработки:** C# (.NET)
* **Пользовательский интерфейс:** WPF
* **СУБД:** Microsoft SQL Server
* **ORM:** Entity Framework
* **Среда разработки:** Visual Studio 2026
* **Методологии проектирования:** IDEF0, UML Use Case (диаграмма прецедентов), реляционное моделирование данных


## Архитектура и ролевая модель

В системе реализовано разграничение прав доступа на основе ролевой модели для 4 категорий пользователей:

1. **Гость:**
   * Просмотр актуального перечня услуг с фильтрацией по категориям и поиском по названию.
   * Просмотр списка специалистов клиники и закрепленных за ними направлений.
   * Регистрация и авторизация в системе.

2. **Клиент:**
   * Управление профилем и ведение базы собственных питомцев (кличка, порода, тип, описание).
   * Онлайн-запись на прием с выбором питомца, специалиста, перечня необходимых услуг и даты визита.
   * Личный кабинет с историей заявок и отслеживанием их статусов (Подтвержден, Завершен).

3. **Ветеринар:**
   * Просмотр личного расписания и назначенных приемов.
   * Завершение записей и фиксация оказания услуг.

4. **Администратор:**
   * Полное CRUD-управление услугами (наименование, категория, стоимость).
   * Управление учетными записями сотрудников и назначение их специальностей.
   * Мониторинг всех заявок и контроль статусов.


## Структура базы данных

Реляционная база данных нормализована до третьей нормальной формы (3НФ) и состоит из **12 связанных сущностей**:

* `User` — учетные записи пользователей (ФИО, логин, пароль, телефон, email).
* `UserRole` — справочник ролей (Гость, Клиент, Врач, Администратор).
* `EmployeeSpeciality` — справочник врачебных специальностей.
* `EmployeeServices` — таблица связи специалистов и оказываемых ими услуг (M:M).
* `Service` — перечень медицинских услуг и процедур с указанием цены.
* `ServiceCategory` — категории услуг (Диагностика, Хирургия, Терапия и др.).
* `Pet` — карточка животного (кличка, порода, особенности).
* `PetType` — справочник видов животных (кот, собака и др.).
* `UserPets` — таблица владения питомцами (M:M).
* `Appointment` — заголовок записи на прием (дата, статус, клиент, врач, итоговая стоимость).
* `AppointmentStatus` — справочник статусов визита.
* `AppointmentServices` — состав услуг, включенных в конкретный прием (M:M).


## Серверная логика и администрирование БД

Для обеспечения целостности данных и исключения ошибок при ручном подсчете сумм, расчет стоимости приема вынесен на уровень сервера СУБД.

Реализован триггер `trg_AppointmentServices_UpdateTotal`, срабатывающий на события `AFTER INSERT, UPDATE, DELETE` в связующей таблице `AppointmentServices`:

```sql
ALTER TRIGGER [dbo].[trg_AppointmentServices_UpdateTotal]
ON [dbo].[AppointmentServices]
AFTER INSERT, UPDATE, DELETE
AS
BEGIN
    SET NOCOUNT ON;

    UPDATE a
    SET a.Total = ISNULL((
        SELECT SUM(s.Price)
        FROM AppointmentServices aps
        JOIN Service s ON aps.service = s.Id
        WHERE aps.Appointment = a.Id
    ), 0)
    FROM Appointment a
    WHERE a.Id IN (
        SELECT Appointment FROM inserted
        UNION
        SELECT Appointment FROM deleted
    );
END;
```

Триггер динамически пересчитывает поле Total в таблице Appointment на основе актуальной стоимости услуг из таблицы Service, обрабатывая как единичные операции, так и пакетные изменения данных.


## Валидация данных и безопасность
* **Валидация входных данных:** проверка логина и пароля на длину (от 4 символов) и допустимый алфавит (латиница), валидация формата мобильного номера телефона.
* **Защита от дубликатов:** контроль уникальности учетных записей пользователей на этапе регистрации.
* **Предупреждение деструктивных действий:** модальные окна подтверждения при удалении записей.
* **Учет требований законодательства:** обработка персональных данных спроектирована с учетом положений ФЗ №152.
